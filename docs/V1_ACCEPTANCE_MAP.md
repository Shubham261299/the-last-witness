# V1 acceptance traceability

All 98 case and 18 UI scenario IDs are mapped below. Their original setup and expected observations remain in the linked design documents. This is a coverage map, **not 116 individually passed end-to-end tests**. Automated assertions cover many requirements together; some checks remain partial/manual. Actual executed counts and limitations are in [verification](V1_VERIFICATION.md).

Fixtures: `player` is a real FastAPI TestClient backed by a fresh temporary SQLite database; `collect_all()` traverses R01–R08. Scoring fixtures independently state all eight proof-role mappings and parameterize every support subset, including irrelevant fillers. Dialogue fixtures parameterize all gated bundles, every proper subset and corrected states. Browser scripts use explicitly disposable `.cache/browser.db`, refuse normal player data, and inject lost responses before/after server commitment. Model samples use only installed local candidates.

Test references below omit the `test_` prefix for readability. [Game/API tests](../backend/tests/test_game.py), [dialogue tests](../backend/tests/test_dialogue.py), [scoring tests](../backend/tests/test_scoring.py), [browser flow](../scripts/check_browser.py), [browser recovery](../scripts/check_recovery.py), and [live model/API checks](../scripts/check_live_api.py) are the executable sources.
